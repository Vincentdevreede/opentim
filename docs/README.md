# Docs

Start with [the code map](code/overview.md) when you need to find your way in the code, and with
[the behaviour research](research/behaviour/README.md) when you need to know what the game does.

## code/: how the code is put together

- [overview.md](code/overview.md): the repo, its packages and apps, the commands, the checks, CI, the scripts and where
  game files come from.
- [behaviour-reader.md](code/behaviour-reader.md): the static reader of TIM.EXE in `packages/content/src/read`: the
  pipeline, `analyseRoutine`, the engine summaries, the pattern matcher, the files by role, and how to check that a
  change keeps every result.
- [descriptions-and-goals.md](code/descriptions-and-goals.md): what turns the report into words and walks
  (`describeBehaviour`), the goals of the puzzles, the level files and the emulator in `packages/content/src/run`.
- [lab.md](code/lab.md): the Lab app: state, the background read, the writer that says expressions in words, the pages
  and components, tests and how to add a name, a tab or a page.

## research/: what we found out about the game

- [behaviour/](research/behaviour/README.md): everything the static behaviour analysis reads from TIM.EXE, by topic:
  reading the report, the Lab, walks, recordings, ropes, other parts, helpers, frames, gears and contact.
- [file-formats.md](research/file-formats.md): the byte layout of the game's files: archives, the map, chunks,
  palettes, sprites and screens, sounds, the sound drivers, language packages, level files and TIM.EXE.
- [levels.md](research/levels.md): what the game does with a level: the goals of the puzzles and what the loader keeps.
- [content.md](research/content.md): part lists, sprites and (future) packs.
- [machine-recorder.md](research/machine-recorder.md): the level recorder that runs a shipped puzzle in the game's own
  code.

## assumptions/: what the code alone can't settle

- [behaviour-assumptions.md](assumptions/behaviour-assumptions.md): the decided assumptions, numbered, each with how to
  recheck it. A test keeps their wording the same as in the code.
- [behaviour-assumptions-all.md](assumptions/behaviour-assumptions-all.md): every assumption the analysis states,
  generated by `list-assumptions`. Don't edit it by hand.

## plans/: work that is still open

- [behaviour-plan-together.md](plans/behaviour-plan-together.md): parts working together. The levels part (L) is done;
  the machine (B, C, D) is open.
- [behaviour-game-checks.md](plans/behaviour-game-checks.md): things to try in the game for parts without a recording.
